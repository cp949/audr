# 테스트 작성과 유지

`packages/*`, `apps/demo`의 소스·테스트를 추가하거나 고치는 작업에 적용한다. 실행할 검증 명령은 [workflow-shared.md](./workflow-shared.md#검증-게이트)의 "검증 게이트"를 따른다. 이 문서는 `superpowers:test-driven-development` 등 스킬의 테스트 지시보다 우선한다.

## 테스트 구성

| 위치                          | 환경                      | 대상                                                              |
| ----------------------------- | ------------------------- | ----------------------------------------------------------------- |
| `packages/audr-core/tests`    | vitest, node              | 편집 연산, 되돌리기 이력, 효과, 인코딩, 녹음기·재생기(가짜 API)   |
| `packages/audr/tests`         | vitest, jsdom             | 컴포넌트, 훅, 드래그 인식, 공개 export, CSS 규칙(포커스·모션)     |
| `apps/demo/tests`             | vitest, jsdom             | 데모 앱 연결                                                      |
| `apps/demo/e2e`               | Playwright, Chromium      | 실제 오디오 경로(`effects`), 파일 가져오기(`import`) |

## 작성 판단

- 테스트를 추가하기 전에 보호할 외부 동작·계약과 예상 결함을 한 줄로 정한다. 정하지 못하면 작성하지 않는다.
- 기존 테스트가 같은 위험을 검증하면 새 테스트를 만들지 않는다.
- 우선 검증 대상:
  - 편집 연산의 샘플 정확성: 자르기·붙이기·효과·구간 경계(1샘플 오차).
  - 되돌리기·다시 실행 이력의 경계와 메모리 상한.
  - 녹음 시작·중지·취소·실패 경로와 마이크·노드 자원 해제.
  - 샘플레이트·채널 수가 다른 입력의 처리.
  - 공개 API 계약: `exports.test.ts`, `publicExports.test.ts`.
  - 키보드·드래그 입력, 포커스 이동, 접근성 이름.
  - Chrome 75 floor 회귀(`pnpm check:browser-floor`).
  - 재현한 버그의 회귀.
- 기본 생략 대상: props를 넘기기만 하는 래퍼 컴포넌트, React가 보장하는 기본 동작, 정적 문구·레이블 하나하나, 타입 검사가 이미 막는 조합, 스타일 값.
  - 예외: 포커스 링·모션 감소처럼 접근성과 브라우저 floor가 걸린 CSS 규칙은 `focusStyles.test.ts`, `motionStyles.test.ts`가 고정한다.
- 형태가 단순해도 데이터 손실(편집한 소리를 잃는 경로)이나 접근성 위험이 있으면 검증한다.
- 테스트 수와 커버리지 수치를 완료 조건으로 삼지 않는다. 테스트를 생략해도 관련 기존 테스트 실행은 생략하지 않는다.

## 개발 방식

- TDD는 버그 수정과 복잡한 상태 전이·계산에 적용한다. 편집 연산, 이력, 녹음기 상태가 대상이다.
- 버그 수정은 회귀 테스트의 RED를 먼저 확인하고 GREEN을 만든다. 기존 테스트가 이미 결함을 재현하거나 선행 테스트가 불가능하면 이유를 기록한다.
- 화면 배치, 문구, 단순 기능 추가는 구현을 먼저 한다. "작성 판단"에 해당할 때만 테스트를 더한다.
- 여러 케이스를 미리 만들지 않는다. 지금 구현하는 동작 하나에 집중한다.

## 실행 범위

- 구현 중에는 고친 파일의 테스트만 돌린다. 한 파일을 한 편집마다 돌리지 않고, 편집을 마친 뒤 1회 돌린다.
  - 예: `pnpm --filter @cp949/audr-core exec vitest run tests/editOps.test.ts`
- `pnpm verify`(전체 단위 테스트 포함)는 커밋마다 `.githooks/pre-commit`이 돌린다. 구현 중에 따로 돌리지 않는다.
- e2e(`pnpm --filter demo test:e2e`)는 브라우저와 기준 스크린샷이 필요해 느리다. 화면·오디오 경로를 바꾼 작업의 병합 직전에 1회 돌린다.
- 기준선 확인을 위해 같은 파일을 다시 돌리지 않는다. 이미 돌린 결과를 쓴다.
- 타입 검사와 lint는 값싸서 자주 돌려도 된다.

## 검증 위치

- 순수 함수·reducer·상태 머신(`audr-core`): 단위 테스트에서 분기를 덮는다. 컴포넌트 테스트에서 같은 분기를 반복하지 않는다.
- 컴포넌트 테스트(jsdom): 사용자가 관찰하는 결과(보이는 문구, 활성 상태, 호출된 콜백)를 검증한다. 대표 정상 경로 하나와 위험한 실패 경로만 둔다.
- 오디오 API(`AudioContext`, `MediaRecorder`류)는 jsdom에 없다. `packages/audr/tests/helpers`의 `fakePlayer`, `fakeRecorder`와 `audr-core`의 가짜 객체를 쓴다.
- 실제 오디오 처리 결과는 e2e에서만 확인한다. fake 마이크만 쓰므로 실제 마이크 품질은 검증하지 않는다.
- `packages/audr-core`에서 검증한 동작을 `packages/audr`에서 다시 검증하지 않는다. 컴포넌트에서는 그 동작을 연결한 결과만 검증한다.
- `toHaveBeenCalledTimes`·`toHaveBeenCalledWith`는 호출 횟수나 인자가 계약일 때만 쓴다(예: 콜백 중복 호출 방지).
- 요구하지 않은 fixture·mock 헬퍼와 테스트 전용 추상화를 만들지 않는다. 테스트를 위해 제품 코드를 복잡하게 만들지 않는다.

## 완료 전 정리

워크플로우(qq)에서 이 정리를 하는 시점과 기록 위치는 [workflow-shared.md](./workflow-shared.md#테스트-정리)가 정한다.

- 새 테스트와 이번에 고친 테스트를 검토한다. 중복, 탐색용, 구현 세부사항에만 종속된 테스트는 통합하거나 제거한다.
- 기존 테스트를 제거하거나 약화하면 보호하던 계약, 대체 검증, 이유를 기록하고 남은 검증을 실행한다.
- 재현한 버그의 유일한 회귀 테스트와 중요한 실패 경로의 유일한 테스트는 지우지 않는다.
- 실패를 없애려고 테스트를 지우거나 조건을 완화하지 않는다. 실패 원인과 계약 변경 여부를 먼저 확인한다.
- 리뷰 지적을 고칠 때 기존 테스트를 지우거나 약화하지 않는다.
- 이번 작업과 관계없는 기존 테스트를 일괄 정리하지 않는다. 그 파일을 고치는 시점에 정리한다.
