# 04. 효과 엔진

`@cp949/audr-core`가 효과를 어떻게 정의하고 적용하는지, 선택 구간과 길이 변화를 어떻게 다루는지 적는다.

- 공개 함수는 `applyEffect`, `planEffect`, `reverseRange`, `EffectName`, `EffectPlan`이다. 이름과 시그니처는 `packages/audr-core/src/index.ts`의 안정 API다.
- `EditSession`이 효과를 부르는 순서와 결과 반영은 [01-sound-editor-edit-flow.md](./01-sound-editor-edit-flow.md)가 다룬다.
- 브라우저 하한은 [ADR-0001](../adr/0001-chrome-75-browser-floor.md)이 정한다.

## 효과는 샘플 배열 함수다

효과 하나는 `EffectDef`다(`effects/segment.ts`). `run(samples, sampleRate, start, end)`가 새 샘플 배열을 돌려주고, `plan(length, sampleRate, start, end)`가 렌더링 없이 결과 길이와 구간을 계산한다. `start`와 `end`는 샘플 인덱스다.

모든 효과가 순수 배열 함수다. Web Audio 노드 그래프와 `OfflineAudioContext`를 쓰지 않는다.

배열 함수로 둔 이유:

- `AudioWorklet`은 별도 모듈 파일 로딩이 필요해 사용처 번들러 설정 부담이 생긴다. 쓰지 않는다.
- `OfflineAudioContext`는 node에 없다. 노드 그래프로 만든 효과는 vitest에서 샘플 단위로 검증할 수 없고 e2e에만 의지하게 된다.
- 배열 함수는 같은 입력에서 같은 결과를 낸다. 잡음과 임펄스 응답은 시드 고정 `mulberry32`(`effects/random.ts`)로 만든다.

도구 함수가 Web Audio 노드와 같은 식을 구현한다.

| 노드                                     | 도구 함수                                                   |
| -------------------------------------- | ------------------------------------------------------- |
| `BiquadFilterNode` lowpass·highpass    | `effects/biquad.ts`의 `biquad`, `crossover`              |
| `WaveShaperNode`(tanh 곡선)              | `effects/shaper.ts`의 `softClip`                         |
| `ConvolverNode`(`normalize = true`)    | `effects/reverseReverb.ts`의 `convolve`, `reverbImpulse` |
| 오실레이터, `DelayNode`, `playbackRate` LFO | 효과 파일 안의 샘플 루프                                          |

`applyEffect`는 이름으로 `EffectDef`를 찾아 `runEffect`를 부르고 결과를 `AudioBuffer`로 감싼다. 배열을 다루는 `runEffect`를 따로 두는 이유는 node에서 `AudioBuffer` 없이 시험하기 위해서다.

## 구간 규칙

구간 효과(`segmentEffect`)는 구간 `[start, end)`만 변환하고 앞뒤 소리를 그대로 이어 붙인다.

- 변환 결과 길이가 달라지면 구간 뒤의 소리가 그만큼 밀리거나 당겨진다. 빠르게·느리게가 그렇다.
- 구간이 2샘플 미만(`MIN_SEGMENT`)이면 효과를 걸지 않고 입력 복사본을 돌려준다. 양 끝 ramp와 `n - 1` 나눗셈이 성립하는 최소 길이다.
- 결과 구간은 변환 뒤의 `[start, start + 변환 길이)`다. `adjustedTrimStart`와 `adjustedTrimEnd`는 이 구간을 결과 전체 길이로 나눈 값이다.
- 구간 밖 샘플은 비트 단위로 같다.
- 음량 효과(크게, 작게, 음소거)는 앞뒤에 소리가 있는 경계에서 구간 안쪽 8ms 동안 배율을 서서히 바꿔 딸깍 소리를 막는다. 소리의 맨 앞이나 맨 끝에 닿은 쪽에는 ramp를 두지 않는다. 두면 소리 전체를 음소거해도 양 끝이 새어 나오고, 작게는 양 끝이 원래 음량으로 남는다.

메아리는 구간 효과가 아니다. 구간의 소리를 원음 위에 겹쳐 더하므로 앞뒤를 밀지 않는다. 결과 길이는 `max(전체 길이, 구간 끝 + 되풀이 횟수 × 간격)`이고, 결과 구간은 입력 구간과 같다.

## 길이를 두 곳에서 계산한다

`plan`과 `run`이 같은 길이를 돌려줘야 한다. trim은 렌더링 전에 알아야 하는 값이어서 `plan`을 따로 둔다. 효과마다 길이 식을 한 함수로 만들어 둘이 같이 쓴다(`speed.ts`의 `speedLength`).

`tests/audioEffects.test.ts`가 모든 효과에서 `planEffect`와 `runEffect`의 길이·trim이 같은지 8000·44100·48000Hz로 확인한다.

## 청각 보호

소리가 커질 수 있는 효과(크게, 메아리)는 결과에 부드러운 상한을 건다(`softLimit`). 0.9 이하는 그대로 두고 넘는 부분만 눌러 절댓값이 1을 넘지 않게 한다.

- 상한은 효과가 값을 바꾼 샘플에만 건다. 크게는 구간 안, 메아리는 되풀이를 더한 영역이다. 그 밖의 원래 소리는 0.9를 넘어도 바뀌지 않는다.
- 뒤집기·페이드·속도처럼 값을 키우지 않는 효과는 상한을 걸지 않는다. 원래 소리를 건드리면 안 되기 때문이다.
- 상한은 효과 정의 안에서 건다. 같은 샘플에 두 번 걸면 값이 다시 눌리므로 한 곳에서만 건다.
- 음량을 입력에 맞추는 효과는 `softLimit` 대신 `matchPeak`의 상한 0.98을 쓴다. 아래 "음량 맞춤"을 따른다.

## 음량 맞춤

음색을 바꾸는 효과는 결과 음량이 입력과 크게 달라진다. 이런 효과는 결과의 최대값을 구간 입력의 최대값에 맞춘다(`effects/level.ts`의 `matchPeak`).

| 효과                                   | `matchPeak` | 이유                               |
| ------------------------------------ | ----------- | -------------------------------- |
| 로봇, 기계 인간, 외계인, 방송, 무전기, 거꾸로 울림      | 적용          | 필터·곱셈·울림이 음량을 바꾼다.               |
| 떨림, 롤러코스터, 스크래치, 따따따                 | 적용 안 함      | 입력 샘플을 다시 읽기만 해서 음량이 거의 변하지 않는다. |
| 크게, 작게, 음소거, 페이드, 메아리, 뒤집기, 빠르게, 느리게 | 적용 안 함      | 음량을 바꾸는 것이 효과이거나 값을 키우지 않는다.     |

- 맞추는 값은 `min(0.98, 구간 입력 최대값)`이다. 1에 닿으면 클리핑하므로 0.98에서 멈춘다.
- 결과나 입력의 최대값이 1e-4 이하이면 키우지 않는다. 무음 입력을 키우면 잡음과 신호음이 크게 들려 청각에 위험하다.
- 다시 읽기만 하는 효과의 음량 유지는 추정이다. 테스트는 절댓값 1 이하만 확인한다.

## 로봇 음성

로봇과 기계 인간은 `effects/robotVoice.ts`의 `voiceEffect` 틀을 같이 쓴다.

1. 구간을 4000Hz(`EDGE_HZ`)에서 낮은 쪽과 높은 쪽으로 나눈다(`crossover`).
2. 낮은 쪽만 음높이를 고정한 기계 목소리로 바꾼다(`robotize`). 결과는 꼬리 0.2초만큼 길다.
3. 높은 쪽을 원음 그대로 더한다.
4. 음량을 고르고(`leveler`), RMS를 입력에 맞춘 뒤(`fitLevel`) 최대값을 맞춘다(`matchPeak`).

끝 자음 살리기(`SIBILANCE` = 1):

- ㅅ·ㅊ·ㅎ 같은 쉬익 소리는 4000Hz 위에 에너지가 몰려 있다.
- 음높이를 고정하면 쉬익 소리도 일정한 윙 소리가 되어 자음이 들리지 않는다.
- 그래서 높은 쪽은 기계 목소리로 바꾸지 않고 원음으로 되돌려 더한다.
- 로봇의 좁은 대역(250~5000Hz)은 기계 목소리에만 건다. 쉬익 소리는 그 뒤에 더한다. 먼저 더하면 5kHz 위가 다시 사라진다.

끝음 살리기(`EVEN` = 0.5):

- 문장 끝 음절은 보통 앞보다 20~30dB 작다.
- 기계 목소리로 바꾸면 작은 음절이 묻혀 들리지 않는다.
- `leveler`가 작은 소리를 최대 6배까지 키우고 큰 소리를 눌러 음량을 고른다.
- 배경 잡음도 같이 커지므로 값을 더 높이지 않는다.

## biquad Q 단위

`biquad`의 `qDb`는 Web Audio `BiquadFilterNode.Q`처럼 dB 단위다. 선형 Q는 `10^(qDb/20)`이다.

- 필터 상수(기본 1, 크로스오버 √½)는 dB 단위 값이다.
- 단위를 선형으로 바꾸면 같은 숫자가 다른 소리를 낸다. 그래서 노드와 같은 단위를 쓴다.
- 크로스오버의 √½은 선형 Q로 약 1.085다. 경계에서 두 쪽이 각각 약 +1.4dB 공진한다. `crossover`의 TSDoc이 이 한계를 적는다.

## 무전기 기준 음량

무전기의 앞뒤 치직과 끝 신호음 크기는 기준 음량(`level`)의 배율이다(`effects/walkie.ts`).

- 기준 음량은 구간 입력의 최대값이다. 입력이 크면 치직과 신호음도 크다.
- 입력이 무음이면 0.3(`FALLBACK_LEVEL`)을 쓴다. 최대값 0을 쓰면 치직과 신호음이 사라져 효과가 들리지 않는다.
- 무음 입력에서는 `matchPeak`가 결과를 키우지 않는다. 그래서 치직과 신호음은 0.3 기준의 고정 크기로 남는다.

## 처리 시간 한계

모든 효과는 동기 순수 함수다. 효과를 처리하는 동안 메인 스레드가 멈춘다.

- 30초 입력(44.1kHz, 구간 전체)에서 로봇은 약 0.35초, 기계 인간은 약 0.31초, 거꾸로 울림은 약 0.12초 걸린다(node 24, Intel i9-14900KF 실측).
- 편집 상한(`maxEditableSamples`, 44.1kHz에서 9,999,999샘플, 약 226.8초)에서 로봇은 약 2.6초, 기계 인간은 약 2.2초, 거꾸로 울림은 약 0.7초 걸린다(같은 환경).
- 브라우저에서는 재지 않았다.
- 더 긴 입력이나 더 무거운 효과에서 메인 스레드를 멈추지 않으려면 처리를 Worker로 옮겨야 한다. 옮길지는 정하지 않았다.
